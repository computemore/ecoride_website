## [1.0.0.9] - 2026-05-20

### Added

- Added copies of `AutoScrollingGallery` section in `src/page-views/ride-page.tsx` and `src/page-views/drive-page.tsx` that continuously pans processed rider-app screenshots across the home page.

- Added this `1.0.0.9.txt` release-note file in `.commits/` following the established 1.0.0.8 structure and detail level.

### Pending

## [1.0.0.8] - 2026-05-16

### Added

- Added a client-side animated hero implementation in `src/page-views/home-page.tsx` using React state/effects (`useState`, `useEffect`, `useRef`) to drive timed layout transitions.
- Added a new `AutoScrollingGallery` section in `src/page-views/home-page.tsx` that continuously pans processed rider-app screenshots across the home page.
- Added new framed preview and marketing image assets:
  - `public/framed-screenshots/framed-home-page.png`
  - `public/home-marketing/processed/01-processed-login-page-phone-otp-page.png` through `15-processed-referrals-page.png`
- Added new design tokens in `src/styles/variables.css` to support stronger gradient surfaces:
  - `--bg-color-ride-gradient`
  - `--bg-color-primary-gradient`
  - `--bg-color-blue-gradient`

### Changed

- Reworked the home hero in `src/page-views/home-page.tsx` from a static centered intro into an animated reveal where:
  - the hero shifts/scales after a timed delay, and
  - a framed app screenshot slides/fades in as a paired visual anchor.
- Replaced the prior 3-card rider-app marketing block with a split layout in `src/page-views/home-page.tsx`:
  - one lead marketing card, and
  - one wide auto-scrolling screenshot gallery.
- Updated marketing card visual behavior in `src/components/widgets/marketing-card.tsx` to support dual-color surface styling (`--card-bg-color` + `--card-bg-color-gradient`) and stronger hover scaling.
- Updated shared surface styling in `src/styles/main.css`:
  - card gradients now use a directional 135deg blend with explicit gradient variable targets,
  - hover interaction changed from slight translate to scale emphasis.
- Adjusted global card geometry in `src/styles/variables.css` by reducing `--radius-card` from `28px` to `18px` for a tighter visual rhythm.
- Added an inline Hero section marker comment in `src/page-views/ride-page.tsx` for readability and structure clarity.

### Validated

- `npx tsc --noEmit -p tsconfig.json` passes.
- `git diff --stat` confirms scope across home page view, marketing card widget, shared CSS variables/main styles, and new screenshot asset directories.
- Home page now references and renders the newly added framed and processed screenshot asset paths.

### Documentation

- Added this `1.0.0.8.txt` release-note file in `.commits/` following the established 1.0.0.7 structure and detail level.

### Pending

- `npm run build` currently fails due to a lint error in `src/components/widgets/marketing-card.tsx`:
  - `Error: Duplicate enum member value #3cdac7.  @typescript-eslint/no-duplicate-enum-values`
- Existing warnings remain (or were introduced) and are still outside this release-note-only scope, including:
  - unused imports/variables in `src/components/widgets/map-office.tsx`,
  - unused variables in `src/page-views/home-page.tsx` and `src/page-views/delete-me-page.tsx`,
  - `@next/next/no-img-element` warnings for image usage in `src/page-views/home-page.tsx`.

## [1.0.0.7] - 2026-04-27

### Added

- Added a new public account deletion information page at `src/app/ecoride-user/delete-me/page.tsx` backed by `src/page-views/delete-me-page.tsx`.
- Added route coverage for the new public delete-me page in `src/app/sitemap.ts` so it is included in the generated sitemap.
- Added a dedicated `account` public route identity in `src/types/navigation.type.ts` and `src/config/site-content.ts` so the delete-me page uses its own orange caution/compliance surface and contextual header links.
- Added a compliance-focused pre-check section and kept the key metadata row visible in the hero so riders and drivers can review the process before starting a deletion request.

### Changed

- Reworked the delete-me page away from the earlier light legal-style wrapper approach and into the same open-section structure used by the stronger branded public pages such as Corporate.
- Switched the full page background to the rider-app warning orange (`#FF9800`) route surface instead of the incorrect red or white presentation.
- Fixed the desktop step-by-step connector layout so each numbered circle now connects cleanly to the next one.
- Moved the retention notice into the same Data and Access card grid as the other account-impact cards.
- Removed the separate “Using More Than One Ecoride Role” section from the live page and left it commented out in code rather than rendering it.
- Updated `src/config/site-content.ts` so `CardContent` now supports the already-used optional `variation` field, resolving the type mismatch that was blocking builds.
- Updated the design-system guidance so major public sections are not wrapped in containers by default and cards are reserved for iterated or grouped content.

### Validated

- `npx tsc --noEmit -p tsconfig.json` passes.
- `npm run build` passes.
- The new `/ecoride-user/delete-me` route is generated successfully as static content.
- Diagnostics are clean for the edited delete-me page, route identity config, and related TypeScript files.

### Documentation

- Updated the `1.0.0.7.txt` release-note file in `.commits` so it documents the final orange-route delete-me implementation rather than the earlier light/legal-style draft.

### Pending

- Existing lint warnings remain in `src/components/widgets/map-office.tsx`, `src/components/widgets/marketing-card.tsx`, and `src/page-views/home-page.tsx` and are still outside the scope of this change.
- Public website authentication is still pending, so the delete-me page currently documents the process and reserves space for future signed-in deletion actions rather than initiating them directly.
