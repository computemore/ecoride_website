Universal Driver Download Route Handler
=======================================

- Added dynamic Next.js App Router route handler at `src/app/driver-download/route.ts`:
  - Handles incoming `GET /driver-download` HTTP requests on `ecoridemw.com`.
  - Performs runtime inspection of incoming `User-Agent` request headers for mobile operating systems:
    - **iOS Detection**: Identifies iPhone, iPad, and iPod mobile Safari user agents using regex `/iPad|iPhone|iPod/i`.
    - **iPadOS / macOS Safari Detection**: Evaluates desktop-class iPad user agents matching `/Macintosh/i` with `/Safari/i` exclusion.
  - Automatically issues an HTTP 302 temporary redirect:
    - **iOS / iPadOS**: Redirects to Apple App Store listing (`https://apps.apple.com/za/app/ecoride-driver/id6765518718`).
    - **Android / Desktop**: Redirects to Google Play Store listing (`https://play.google.com/store/apps/details?id=com.computemore.ecoridedriver`).
  - Seamlessly complements the existing `/download` route handler (used for rider app downloads).

TypeScript Strictness and Download Hook Typing Repairs
=====================================================

- Refined `src/hooks/use-driver-download-url.ts` and `src/hooks/use-rider-download-url.ts`:
  - Removed unchecked `(window as any)` type assertions in client device evaluation logic.
  - Introduced typed browser window shape `Window & { opera?: string; MSStream?: unknown }` to safely check Opera and legacy IE mobile properties without bypassing compiler constraints.
  - Resolved ESLint rule `@typescript-eslint/no-explicit-any` across both client hooks.
